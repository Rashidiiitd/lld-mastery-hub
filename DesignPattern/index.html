Interview approach

  1. Explain the problem in plain language.
  2. Show the straightforward design first.
  3. Identify what varies or becomes tightly coupled.
  4. Introduce the pattern only if it addresses that pressure.
  5. Discuss trade-offs and whether simpler code would be better.
